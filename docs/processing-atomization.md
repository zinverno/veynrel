# Processing: consent and preview for generative atomization

The primary Processing card now performs single-note atomization. Review vault remains an independent list-first section. Batch and MOC keep their existing launchers, selection, preparation and generator. No new settings, dependencies, versions, journals or ranking changes are introduced.

## One owner, explicit stages

`main.ts` retains `atomizeNote()` and the `ai-atomize-note` command, but all entrances now open `GenerativeAtomizationModal`. The Processing button first opens Obsidian's Markdown picker with full paths. The editor menu binds the file supplied by the native menu event, rather than a later active file. Concurrent launches for one file share a modal lifetime; plugin teardown cancels outstanding UI work.

`atomization/generativeSession.ts` extracts the existing generative workflow: the existing atomization prompt, `smartTruncate`, `callOpenRouter`, transport parser, `extractJSON`, atom template and filename/link helpers. It preserves the 3000-token output limit and legacy `Name-2.md` suffix convention. There is exactly one explicit request per consent, including failures. No automatic retry remains in atomization. Finish reasons must indicate a complete response before proposals are accepted. The strict fragment-transfer planner and existing-empty-note Apply/Undo path are unchanged; their guarantees are not claimed for this generator.

Consent identifies provider/model, saved file/path, full or section-shortened input and possible cost. The exact frozen sent text is visible, including truncation markers; the system prompt is accessible through a secondary button. Unsaved editor text is excluded. Opening, preparing and cancelling before consent perform no requests or folder/file writes. Cancelling an in-flight `requestUrl` stops waiting and ignores late results; it cannot retract a request already sent.

Proposals are immutable UI snapshots. Each checkbox selects one proposed title, exact future Markdown and canonical destination. Literal previews do not render model-provided embeds or execute HTML. They are human-reviewed suggestions, not verified facts or guaranteed independent knowledge. Excluding proposals and going back are read-only. The separate write review lists exact paths/count and the complete source suffix. It keeps every byte of the original, including trailing whitespace and CRLF, then appends only the approved link block.

## Write boundary and partial results

Before review and immediately before each write, the service rechecks source file identity, path, complete content and stats; language/model/destination settings; folder identity/absence; all approved destinations; and any files already created during this session. Path validation is reused from the existing atomization planner. Collisions include case/Unicode-equivalent loaded paths, folders and adapter-visible paths. Names never silently change after review. Pending destination folders are created only after explicit write confirmation.

The existing saved-editor guard blocks writes while affected tabs are open. An explicit secondary action can close matching saved tabs, including popout leaves, after checking every affected buffer. It refuses to close an unsaved or unavailable buffer. This lets editor-origin sessions continue without a second model request and without silently discarding edits. Fresh checks still run after closing tabs. Source replacement uses the existing `replaceNoteIfUnchanged`, including its check inside `Vault.process`.

Only one atomization write may run per app. Files are created sequentially; the first failure stops further work. The result distinguishes verified created paths, unfinished paths and an unconfirmed attempted write. The source link block is written only once all selected output files have been verified. Explicit retry rechecks the same plan, verifies prior created files and creates only still-absent targets; it makes no model request. An ambiguous write remains blocked. No deletion, fabricated rollback, universal Undo or crash recovery is promised. Folder creation can remain after a failed write.

**Platform limit:** public `Vault.create` does not provide a cross-process exclusive-create transaction. Fresh collision checks and app-local serialization preserve and strengthen the legacy protection, but cannot reserve a path against another program writing between check and create. The previously rejected experimental desktop exclusive-create executor is not activated. Avoid concurrent external writes to the destination; this workflow is not the journal-backed strict Apply/Undo executor.

## Verification and evidence

Unit/transport tests exercise exact consent/request text (including truncation), cancellation and late completion, malformed proposals and completion reasons, source edits/rename/identity replacement, destination/settings changes, unsafe paths, suffix collisions, affected editors, partial failure/retry, ambiguous writes, source changes inside `process`, duplicate entrances and app-local serialization. Processing UI tests retain the two lower actions and independent sidebar Review. Existing MOC, processing and Review regression suites remain enabled.

`scripts/review-flow-native.mjs <new isolated artifact directory> <frozen build> atomization` uses real Obsidian input and a local HTTP response through the product builder/parser. It records picker/consent, proposal exclusion and cancellation, exact review, stale/collision refusal, injected filesystem failure and partial retry, editor command and actual context menu, explicit saved-tab closure, RU/EN, both built-in themes, 1280/390 px, keyboard, contrast and 200% Electron zoom. It checks original Markdown hashes and exact sent input. Synthetic failure injection is labelled; no live model quality or billing claim is made.

The permanent frozen kit contains the exact source SHA, three artifacts and hashes, full native frames/video, test/check logs, CI artifact comparison and installer. The existing `processing-after` and `integration` native scenarios additionally cover unchanged MOC/Batch and Review Apply/Undo. Personal vaults and TEST are neither read nor modified. Mobile, custom themes, live providers, concurrent external-write atomicity and process-crash recovery are outside this acceptance.
