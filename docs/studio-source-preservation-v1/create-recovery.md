# Create-only plan and recovery

Admission rereads every selected saved source and verifies full text, object identity, creation/modified time and byte count. Read Guard permits inspectable saved buffers; unsafe/unknown/deferred editable views fail closed. Targets must be canonical `.md` paths in the existing source parent, outside hidden/service/config areas, different from the source, and unique under NFKC/case comparison. Checks inspect cached files and adapter directory entries, including case/Unicode collisions and occupied directories. Ambiguous source-link resolution refuses the plan.

Suggested suffixes are offered only before confirmation. After confirmation no suffix, rename, overwrite or parent creation occurs. An immutable intent is written and reread before dispatch. Source/target/operation guards are repeated before native `Vault.create`. The created file is reread with identity/stat checks, compared to the exact payload and followed by an immutable receipt. Only then is it reported created.

The new namespace is `<configDir>/plugins/ai-knowledge-hub/studio/markdown-create/<plan-id>/`. Schema 1 `intent.json` holds a checksum-sealed plan, source snapshots and output. Separate dispatch/created/not-created markers reference the intent hash. These files contain **local plaintext note content**, not encryption or authenticated tamper evidence. Raw model responses are not redundantly stored here. Existing Apply backups/receipts and diagram formats are unchanged. Malformed/unreadable evidence blocks new creates; damaged evidence is never overwritten.

An issued create with failed readback/receipt is `unconfirmed`, even when a file visibly exists. A batch stops dispatching further files after a write/receipt error; earlier receipts remain valid and remaining rows are skipped. Cancellation before dispatch creates no note; an already issued create is still observed. Duplicate/stale confirmation cannot start another final attempt. Pre-write admission refusal retains the same Review and requires fresh checking, with no generation.

After restart history reads saved evidence and current targets only on explicit history inspection. It never retries, creates or deletes a file. Unconfirmed observations can be reviewed and separately acknowledged: exact target text/stat and journal evidence are checked again, then only a receipt is written. Changed targets remain modified/unconfirmed. A hash/name match is never permission to delete. There is no automatic Undo for new notes; the existing guarded source Undo remains separate.

Guarantees are in-process checks and the public create-only API. There is no OS exclusive-create claim, filesystem fsync, cross-process transaction, or atomic 20-file batch. Do not reuse a potentially dispatched target automatically after unknown outcomes.
