# Протокол: Connection Opportunities на 40 заметках

Статус при первоначальной фиксации протокола: результаты ещё не рассчитаны.
Теперь опыт выполнен; наблюдения находятся в [results.md](results.md). Это новый прогон
Connection Opportunities на **синтетическом**, публичном корпусе с ранее
вычисленными настоящими embeddings. Предыдущие Rerank-испытания не являются
результатами этого исследования.

## Вопрос и критерий

Может ли сравнение семантических соседей с Markdown-ссылками предложить
конкретное действие после чтения обеих заметок? Частоту человеческой полезности
этот агентский прогон не определяет: каждый пользовательский verdict остаётся
`Requires human review`. Высокий cosine, mutual rank и общие соседи не заменяют
оценку намерения автора.

## Данные и исходные условия

Состав и порядок отбора зафиксированы в [protocol.json](protocol.json) до
расчёта карты. Взяты 40 заметок из публичного MIT-корпуса
[`rerank-hard-v1`](../../../tests/fixtures/rerank-hard-v1/README.md), объединённые
темой надёжности сервисов и операций с данными. Это вымышленные учебные ситуации,
включая фразы от лица условного автора; они не описывают опыт автора Veynrel.
Личные vault не читались и не копировались.

Существующий showcase на 500 заметок отклонён: его опубликованный
[аудит](../../showcase500-rerank-v1.md) устанавливает шаблонность содержимого,
а исходные тексты оставались непубличными. Публичный содержательный fixture
позволяет не сочинять новый корпус под полученные ранги.

Тела выбранных заметок сохраняются дословно. До расчёта добавлены семь направленных
ссылок (шесть неориентированных пар) в YAML `related`. Это искусственно заданное
начальное состояние, а не исторические действия пользователя. Topology читает
`frontmatterLinks`, chunker исключает frontmatter: embedding-входы остаются
байт-в-байт прежними. Ни одна ссылка не подбирается по результату cosine.

## Процедура

1. Проверить происхождение кэша по хешам точных embedding-запросов и векторов.
2. Пересобрать индекс production-цепочкой MarkdownChunker → IndexingService →
   LocalVectorStore с кэшированными векторами. Неизвестный текст — ошибка,
   никакой сетевой запасной ветки.
3. Рассчитать Global Semantic Map и Connection Comparison штатными реализациями.
4. В отдельном Obsidian открыть тот же корпус и индекс; сравнить native snapshot
   с вычислительным прогоном, проверить ранги, фильтры, evidence, shared neighbors.
5. Взять первые десять различных Candidate при mutual top-3, пустом поиске,
   review All и выключенном Hide Excalidraw. Сортировку не менять. Если десяти
   нет, зафиксировать недостаток без расширения выборки.
6. Прочитать обе заметки каждой пары; отдельно записать наблюдение,
   техническую интерпретацию, действие и ограничение. Не назначать Useful.
7. Для первой обоснованной по содержимому пары добавить одну ссылку в тестовую
   копию. Проверить переход Candidate → Aligned и действительную навигацию.
8. Отдельно временно скрыть метаданные одного конца: такие пары должны стать
   unclassified, а не Candidate. Восстановить источник. Это внесённый сбой.
9. Проверить жизненный цикл сессионных verdicts отдельно от оценки полезности.
10. Сохранить три настоящих снимка Obsidian и сырой отчёт; при недоступной среде
    явно оставить native-проверку и снимки NOT RUN.

## Ограничения

Корпус создан агентом для другого исследования, затем тематически отобран.
У него нет органической истории ручных ссылок. Тест зависит от выбранных 40
заметок и модели; top-5 меняется при добавлении других заметок. Отбор mutual
top-3 и общих соседей смещает выборку к плотным тематическим группам.
Первый индекс будет восстановлен из кэша, а не получен новым provider-вызовом.
Это не испытание качества индексации Ollama или текущего удалённого API.
Единственный агентский разбор не является независимой человеческой оценкой.
Десять пар не дают оценки precision всего vault, экономии времени или спроса.

## Повторение без API-ключа

Из корня checkout этой ветки, с Node 24 и установленным desktop Obsidian:

```sh
npm ci
npm run build
node scripts/connection-case-study.mjs /tmp/veynrel-connections-repeat
```

Последняя команда требует **новую** директорию непосредственно в `/tmp`,
восстанавливает production-индекс, делает independent set-join assertions,
проверяет неполные метаданные и сравнивает весь JSON результата с опубликованным
`offline.json`. Она создаёт `vault/`, изолированный `profile/`, `offline.json`
и `snapshots.json`. Повторное использование существующего пути отклоняется.
Результат этого этапа — вычислительная проверка; это ещё не запуск Obsidian.

Использованный Linux запуск (пути бинарников зависят от дистрибутива):

```sh
electron43 /usr/lib/obsidian/app.asar \
  --user-data-dir=/tmp/veynrel-connections-repeat/profile \
  --remote-debugging-port=19644 --remote-debugging-address=127.0.0.1 \
  --disable-gpu --ozone-platform=x11 --no-sandbox \
  --proxy-server=http://127.0.0.1:9 '--proxy-bypass-list=127.0.0.1;localhost'
```

В опыте процесс получил только PATH, HOME, DISPLAY, WAYLAND_DISPLAY,
XDG_RUNTIME_DIR, DBUS_SESSION_BUS_ADDRESS, LANG и XAUTHORITY; исходный профиль
Obsidian не копировался. `--no-sandbox` — параметр исследовательского запуска
Electron, не рекомендация для повседневного vault. Держите CDP только на loopback
и закройте это окно после опыта. Порты 19643 и 19644 должны быть свободны.

Когда открылся подготовленный vault, во втором терминале:

```sh
node scripts/connection-case-study-native.mjs \
  http://127.0.0.1:19644 /tmp/veynrel-connections-repeat
```

Сценарий проверяет точный путь vault, подключает реальный интерфейс, запускает
локальную выдачу кэшированных векторов, выполняет контрольные действия и одну
явную правку тестового Markdown. Он создаёт `native.json` и `assets/*.png` в
директории прогона, затем закрывает сервер кэша. Окно остаётся открытым для
осмотра. После закрытия сервера не продолжайте индексирование изменённых текстов:
оно будет недоступно; для нового опыта создайте новую копию. Индекс для просмотра
карты уже загружен. Приватный vault и ключи для повторения не нужны.

Скрипты содержат assertions на неизвестный embedding-вход, размер/хеш векторов,
идентичность baseline, десять различных пар, категории, границы metadata,
изменение ровно одного файла и отсутствие embeddings до note-opening. Native
checks не выдают успешный результат, если Obsidian не подключён.

## Три иллюстрации и ручная оценка

1. До сравнения: Discover → Global Semantic Map, 40 indexed / 40 mapped.
2. Connection Opportunities → Candidate → Mutual top-3 → первая пара 019/040.
   В инспекторе видны 0.711, ранги 1/1, соседи 021/039/046 и No Markdown link.
3. После исследовательской правки: открыть 019 и 040 рядом в Reading view;
   в Properties 019 виден `related → note-040`, рядом доступны оба полных текста.
   После refresh в сравнении: 138 Candidate, 6 Aligned, 1 Explicit-only.

Новые оригиналы и хеши: [assets/manifest.json](assets/manifest.json). Снимки
получены через CDP, без нарисованного интерфейса, масок и изменения поведения
продукта. Каждый визуально просмотрен агентом. Electron capture здесь
исследовательский CDP-сценарий; Playwright/editorial-kit capture не запускался.

Для человеческой оценки сохраните свой отдельный CSV до refresh или закрытия:
на каждую пару нужны Useful / Not useful / Unsure, конкретное действие и ответ,
была ли связь уже известна. Сессионные verdicts продукта не сохраняют историю.
Отдельно считайте пользовательские ответы только для этой cohort; не переносите
их на весь vault. Контрольные нажатия агента такими ответами не являются.
