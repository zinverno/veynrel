# Русскоязычный опыт: рабочие заметки об архитектуре и обучении

**Корпус согласован по пяти образцам и завершён: 40 синтетических заметок.**
Подача одобрена, пользовательские оценки связей ещё не получены. Этот пакет
содержит учебные ситуации, варианты решений и вопросы для будущих проверок.
[Протокол](experiment.md), [замороженные входы](protocol.json) и
[происхождение всех 40 заметок](sources.csv) зафиксированы до расчёта кандидатов.

## Источник и изменение замысла

Основа — публичный синтетический корпус в [../corpus/](../corpus/), лицензия
репозитория MIT, исходная версия
`2ae9a19e80524131a15bd78dba91ff2b7f34f78f`. Первые буквальные переводы доступны
в [коммите fe772ea](https://github.com/zinverno/veynrel/tree/fe772ea1068dc8264705a80d576cfb2c1e494ec4/docs/case-studies/connection-opportunities/ru).

Текущая редакция — **тематическая адаптация, а не чистый перевод**. Акцент
перенесён на архитектурные решения вокруг обучения моделей и работы с данными.
Тексты подготовлены агентом. В них нет описаний личного опыта автора, реальных
инцидентов, проведённого обучения или измеренной стоимости пересчёта. Вопросы
и будущие проверки внутри заметок — часть учебного сценария.

[Исходный опыт](../index.md) остаётся отдельным baseline со смешанным языковым
составом. Его корпус, векторы, наблюдения и изображения не изменены. Корневые
скрипты воспроизведения пока работают только с ним.

**Сравнение не сможет выделить эффект языка:** теперь одновременно меняются
язык, стиль, длина и содержание заметок. Можно будет сопоставить работу одного
алгоритма на двух описанных корпусах. Приписывать разницу русскому языку или
называть её улучшением качества без человеческой оценки нельзя.

Это образцы для обсуждения подачи, **не будущая десятка кандидатов**. Исходные
заметки уже встречались в baseline; оценка после знакомства с ними не будет
слепой. После выбора подачи корпус нужно завершить и зафиксировать до расчёта.
Ни один текст не проверялся по cosine и не подгонялся под прежний порядок пар.

Имена файлов и frontmatter сохранены. У этих пяти исходных заметок нет исходящих
Markdown-ссылок; у адаптаций их тоже нет. Полный корпус должен сохранить семь
исходных направленных ссылок из [протокола baseline](../protocol.json).
При адаптации остальных текстов нужно проверить, остался ли понятен смысл
каждой такой ссылки, и описать расхождения. Число разделов и формулировки уже
не обязаны совпадать с оригиналом; считать это точным переводом нельзя.

## Проверка технических утверждений

Состояние оптимизатора и номер эпохи при возобновлении обучения сверены с
[руководством PyTorch по checkpoint](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html#saving-loading-a-general-checkpoint-for-inference-and-or-resuming-training).
Оговорки о случайности и различиях окружений — с
[PyTorch Reproducibility](https://docs.pytorch.org/docs/main/notes/randomness.html).
Источники проверены 2026-10-14; обучение модели в рамках подготовки текстов
не выполнялось. Список в заметке 007 — набросок для конкретного будущего цикла,
а не универсальный рецепт восстановления любого training pipeline.

Для 045 граница гарантии следует из самого описанного правила: ресурс хранит
максимальный **принятый** номер, поэтому ещё не полученный номер ему неизвестен.
Это техническая интерпретация сценария, не результат выполненного fault test.
Остальные базовые механизмы взяты из связанных выше исходных заметок; новые
варианты применения явно сформулированы как условные решения.

Источники вынесены сюда, за пределы корпуса, чтобы не менять структуру ссылок
между заметками. Этот README не должен индексироваться как часть будущего vault.

## Следующий шаг

После фиксации корпуса — новый локальный расчёт, затем оценка первых десяти
автором небольшими группами. Старые векторы не используются. Платные запросы
требуют отдельного согласия; для выбранной локальной модели они не нужны.

Оценки найденных связей появятся в репозитории только после их получения и
одобрения автором для публичного использования. Техническая интерпретация
хранится отдельно. Сам Veynrel не создаёт ссылки автоматически; Useful /
Not useful / Unsure живут только в сессии интерфейса и сбрасываются при новом
снимке сравнения.

## Проверки

2026-10-14 на второй редакции повторно прошли 2910 тестов в 115 файлах и
`npm run lint`, включая `npm run typecheck` и `npm run build`. Осталось прежнее
предупреждение о `fetch` в `api.ts:402`, без ошибок.

Отдельная проверка подтвердила: ровно пять файлов, исходные frontmatter и ссылки
сохранены, локальные ссылки README разрешаются, корпус и доказательства baseline
не изменены, `git diff --check` чистый. Первый запуск этой проверки остановился
на ограничении песочницы `spawnSync git EPERM`; повторный запуск прошёл.
Проверки проекта не оценивают естественность текста и не являются испытанием
нового корпуса в Obsidian.
