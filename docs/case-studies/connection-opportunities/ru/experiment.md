# Протокол русскоязычного опыта

Вопрос: какие связи появятся между рабочими заметками об архитектуре и обучении
моделей и какие из первых десяти автор сочтёт полезными? Технический расчёт и
оценка человека — разные этапы. Отсутствие ответа не является отрицательной оценкой.

## Корпус

40 синтетических заметок, адаптированных из публичного MIT baseline. Пять
образцов из `5bfebec` сохранены без изменений после согласования подачи.
Остальные адаптированы до вычисления кандидатов. Имена исходных файлов и семь
направленных ссылок сохранены; это шесть неориентированных связанных пар.
Две пары близких заметок о DNS и QUIC намеренно не объединены. Требования и
различия задач сохранены, а не сглажены для роста similarity.

В тестовом vault файлы получают русские названия с числовым ID, чтобы карта
была читаемой. Ссылки переводятся через ту же таблицу соответствия. Это взаимно
однозначное переименование, не добавление рёбер. Заголовки и тела не меняются.
Все исходные хеши, пути и параметры — в [protocol.json](protocol.json).
README и исследовательские документы не входят в индекс.

## Модель и ограничения сравнения

Используется уже скачанная локальная
[paraphrase-multilingual-MiniLM-L12-v2](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2),
revision `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`, Apache-2.0,
CPU float32, mean pooling из конфигурации модели, L2 normalization, batch 8,
4 вычислительных потока. Новые векторы считаются по новым текстам без сети.

Стандартный лимит модели — 128 токенов; поддерживаемое число позиций — 512.
Предварительный аудит production-чанков дал 50 входов, максимум 304 токена;
43 входа длиннее 128. **До расчёта пар выбран max_seq_length=512.** Это явное
изменение конфигурации, качество модели на длинных входах отдельно не измерено.
Скрипт откажется считать опыт при любом входе длиннее 512, а не обрежет его молча.

Модель отличается от baseline `openai/text-embedding-3-small`. Вместе меняются
язык, стиль, содержание, длина и модель. Разница чисел не выделяет эффект языка.
Один русский smoke probe и повторное кодирование проверяют запуск, форму и
стабильность вычислений; они не устанавливают качество поиска на корпусе.

## Порядок до человеческой оценки

1. Зафиксировать корпус и этот протокол отдельным коммитом до embeddings и пар.
2. Получить chunks действующим MarkdownChunker с неизменными defaults.
3. Локально рассчитать новые векторы; сохранить hashes модели, входов и float32.
4. Построить индекс через production IndexingService, Global Map через
   SemanticDiscoveryService, сравнение через deriveConnectionComparison.
5. Выбрать Candidate / mutual-top-3 / review All, без поиска и скрытия
   Excalidraw. Взять первые десять различных пар в штатном порядке:
   rank bucket, общие соседи по убыванию, точный cosine по убыванию, пути.
   При нехватке сохранить меньшую группу, фильтр не расширять.
6. Сохранить **все** пары и полный порядок. Проверить счётчики независимым
   пересечением множеств. Проверить исключение пар при отсутствующих метаданных.
7. Загрузить индекс в отдельном настоящем Obsidian, получить native topology,
   сверить полные пары/ранги/соседей с вычислительным прогоном. Проверить фильтры
   и сделать первые два снимка. Не менять Markdown и не ставить verdicts.
8. Прочитать оба текста каждой выбранной пары, записать только техническую
   интерпретацию и возможное действие. Передать автору небольшими группами.

Автор отвечает: Useful / Not useful / Unsure; создал бы ссылку — Да / Нет /
Возможно; короткая причина. Публикация ответов требует его одобрения.
Практическое действие и третий снимок ждут конкретного согласованного решения.
Если полезной пары не будет, отрицательный результат сохраняется.

## Воспроизведение

Из корня репозитория после `npm ci` и `npm run build`:

```sh
node scripts/connection-case-study-ru.mjs inputs /tmp/veynrel-ru-inputs-new.json
# Для нового расчёта: подготовленный Python с пакетами из vectors.json,
# локальная папка указанной revision модели и пустая выходная директория.
python scripts/connection-case-study-ru-embed.py /tmp/veynrel-ru-inputs-new.json MODEL_SNAPSHOT EMPTY_OUTPUT
# Сохранённые в этом пакете векторы позволяют повторить расчёт без Python:
node scripts/connection-case-study-ru.mjs prepare /tmp/veynrel-ru-repeat
```

Команда `prepare` создаёт новый одноразовый vault и профиль, не принимает
существующий каталог и не обращается к провайдеру. Повтор использует только
векторы с совпавшими хешами новых русских входов. Новая генерация сохраняется
отдельно; скрипт не перезаписывает опубликованные векторы. Численная идентичность
на другом оборудовании не обещается; эталон — сохранённый float32.

## Native-воспроизведение, Linux

После `prepare`, в графической сессии с доступом к DISPLAY и XAUTHORITY:

```sh
/usr/bin/electron43 /usr/lib/obsidian/app.asar \
  --user-data-dir=/tmp/veynrel-ru-repeat/profile \
  --remote-debugging-port=19644 --remote-debugging-address=127.0.0.1 \
  --disable-gpu --ozone-platform=x11 --no-sandbox \
  --proxy-server=http://127.0.0.1:9 --proxy-bypass-list='127.0.0.1;localhost'
# Во втором терминале, после появления окна:
node scripts/connection-case-study-ru-native.mjs http://127.0.0.1:19644 /tmp/veynrel-ru-repeat
```

Это точный вариант текущего Linux-окружения, не универсальная команда установки
Obsidian. Применять только к созданному скриптом синтетическому профилю;
нельзя направлять CDP-сценарий на личный vault. Оба localhost-порта должны быть
свободны. На других системах нужен соответствующий исполняемый файл Obsidian.

Скрипт проверяет путь vault, ключи, модель и совпадение Markdown-хешей. Он
загружает индекс и реальные metadata Obsidian, сохраняет native.json и два PNG,
не создаёт ссылок и не выставляет verdicts. Каждый запуск — новый каталог.
Старые снимки не перезаписываются; новые нужно просмотреть перед публикацией.
Контролируемое скрытие metadata восстанавливается в finally даже при ошибке.

Текущий прогон: Obsidian 1.13.7, Electron 43.6.0, Veynrel 2.1.0, Linux;
SHA-256 main.js `b486f747a407aa4aee5229378aa5446d6c766a45a1087c46bff966d3e736031c`.
Новая семантика рассчитана Python, native-прогон **загрузил** полученный индекс.
Пользовательские verdicts в Veynrel существуют только в сессии и очищаются
новым snapshot; плагин не создаёт ссылок автоматически.
