# Несколько загрузок артефактов в одном соединении

HTTP/2 умеет несколько потоков запросов поверх TCP. Но потерянный TCP-сегмент задерживает последующие байты до восстановления. Приложение может ждать на разных потоках из-за потери в общем соединении.

У QUIC упорядоченная доставка независима для разных потоков. Потеря в одном не обязана задерживать уже доступные данные другого. Это полезное различие, но ещё не обещание ускорения загрузки.

Общая пропускная способность и управление перегрузкой никуда не исчезают. В пострадавшем потоке тоже придётся ждать. Если один запрос логически зависит от другого, транспорт эту зависимость не снимет. Нужны трассы при потерях; таких измерений здесь пока нет.
