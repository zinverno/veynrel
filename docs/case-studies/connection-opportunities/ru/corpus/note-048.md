# CSV с разметкой: где испортить данные ещё до обучения

## До парсера

Пришла таблица с именами примеров, количеством и числовой оценкой. Сначала сохранить исходные байты и их контрольную сумму. Импорт идёт в staging, не прямо в рабочий датасет. Расширение файла не гарантирует формат; параметры экспорта нужны рядом с партией.

Кодировку подтвердить явно. Иначе имена могут превратиться в символы замены ещё до разбора колонок. Проверить кириллицу, не выкидывать недекодируемые байты молча. Переводы строк могут отличаться. BOM должен обрабатываться по правилам декодера или парсера, а не удаляться из произвольных мест.

## Строки и поля

Нужен CSV-парсер с кавычками, разделителями внутри поля и переносами строк. Обычный split по запятой сломает такую строку. Обязательные заголовки должны присутствовать ровно по одному разу. ID строки сохранить для диагностики.

Пустое поле, отсутствующая колонка и числовой ноль — разные состояния. Сводка импорта должна показывать принятые и отклонённые строки. Частично прочитанную партию нельзя объявлять полной.

## Десятичная запятая

Для этой условной партии разделитель колонок — точка с запятой, десятичный — запятая. Сначала разобрать CSV, потом числовую колонку в объявленном формате. Поле 12,50 становится числом 12.50, а не двумя полями.

Заменить все запятые в исходном файле нельзя: заденет текст и quoted-поля. Для разделителей тысяч нужно отдельное правило. Пустая оценка не должна превратиться в ноль. До принятия партии хранить исходный текст поля с диагностикой и проверить все строки, не только несколько удачных.

## Публикация

Принятые данные записать транзакцией или новым поколением, публиковать после проверки. При сбое остаётся рабочим предыдущее. В журнале — хеш источника, настройки парсера и ID отклонённых строк. Исправленная партия получает новый ID; старую ошибку не затирать.
