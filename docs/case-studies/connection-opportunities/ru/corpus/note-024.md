# Два человека правят конфиг эксперимента

Открыть запись вместе с номером ревизии. При сохранении передать ожидаемую ревизию, а в базе заменить запись только при совпадении номера. Успешно — увеличить номер. Ноль изменённых строк — конфликт, нужно перечитать или объединить правки.

Так не требуется держать блокировку всё время, пока человек смотрит форму. Timestamp с грубой точностью — сомнительная замена счётчику: две правки могут попасть в один момент по этим часам.

Самое неудобное место будет в интерфейсе. Нельзя просто повторить старую замену с новым номером: получится потеря чужих изменений, от которой и защищались. Пока нужен понятный сценарий показа конфликта.
