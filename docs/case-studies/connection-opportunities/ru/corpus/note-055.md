# Восстановить статус экспериментов из журнала

Последовательность принятых событий позволяет заново собрать проекцию после сбоя. Позицию checkpoint сохранять после того, как само состояние надёжно записано. Потом читать события после этой позиции. Для повторной доставки нужны правила идентичности и порядка событий.

Пересобрать экран со статусами — одно. Повторно отправить внешний запуск обучения из replay-цикла — совсем другое. Событие описывает принятое действие, а потерянный ответ внешнего сервиса может оставить этот факт неизвестным.

Побочные эффекты не должны выполняться из незащищённого replay. Снимки ускоряют восстановление, но надо проверять соответствие снимка позиции в журнале. Пока хочется разделить чистое построение состояния и реальные команды внешнему миру.
