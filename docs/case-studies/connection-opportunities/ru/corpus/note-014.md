# Журнал экспериментов на SQLite: чтение во время записи

Для небольшого локального трекера хочется читать историю запусков, пока обучение дописывает метрики. В WAL читатель держит свой снимок, а другое соединение добавляет изменения в журнал. Копировать живую базу ради каждого отчёта не нужно.

Но писатель всё равно один. Длинный читающий запрос может задержать checkpoint и раздуть WAL. Сначала посмотреть длительность транзакций, потом трогать таймауты.

Режим WAL включается явно. Файлы базы, WAL и shared memory участвуют в одной схеме работы; копия одного живого файла не становится от этого корректным backup. Отдельно решить, как делать резервную копию и когда читатели отпускают снимки.
