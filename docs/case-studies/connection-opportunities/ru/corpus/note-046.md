# Индекс датасета решил, что все файлы удалены

## Что хранится где

Предположим, исходные изображения лежат на съёмном диске, система — на другом. Сканер собирает каталог размеров и контрольных сумм. По каталогу удобно выбирать данные без чтения каждого оригинала. Каталог пересоздаётся, а исходникам нужны отдельные копии. Поколение связывать с конкретным диском, а не с его подписью в файловом менеджере.

## Опасное место в обходе

Удалять записи каталога о пропавших файлах можно только после полного успешного обхода. Нет прав на каталог — значит сканирование неполное. Если считать его пустым, проблема доступа превратится в удаление данных из индекса.

Предыдущий каталог держать до фиксации новой транзакции. В итогах нужны посещённые корни и полнота каждого. Один общий статус «готово» здесь слишком мало говорит.

## После замены диска

Проверить подключение, файловую систему и свободное место. Имя устройства вроде /dev/sdb может поменяться. А точка монтирования без диска остаётся обычным каталогом — доступным и пустым. Сканер может честно обойти его и сделать неправильный вывод.

## Перед очисткой индекса

В конфиге — ожидаемый UUID файловой системы и файл-маркер на ней. До обхода проверить оба. Нет совпадения — остановиться без удаления записей. После проверенной замены диска ожидаемый ID меняется явно. Симлинк на старый путь этого не заменит.

Сначала сверка без удаления: число файлов и выборочные контрольные суммы против прошлого каталога. Только потом включать очистку. Пустая папка от установщика не означает пустой датасет.

## Незавершённое

Нужна схема монтирования и расположения backup, без секретов восстановления внутри каталога. Пробное восстановление — в другой каталог. При неудачном переезде оставить оригиналы и прошлый индекс для разбора. Такой переезд в этом сценарии ещё не выполнялся.
