# Что сохранять между эпохами

Обучение идёт долго. Хочется пережить падение процесса и продолжить с понятного места. Просто сохранить веса недостаточно: у оптимизатора тоже есть состояние, которое влияет на следующие шаги.

Пока вариант — сохраняться на границе эпохи. В checkpoint положить состояние модели и оптимизатора, номер завершённой эпохи. Рядом — конфиг запуска, ревизию кода и идентификатор данных. Если есть scheduler, его состояние тоже придётся учитывать.

Запись сначала во временный файл, проверка, затем публикация готового checkpoint. Номер завершённого шага нельзя продвигать раньше, чем соответствующее состояние надёжно сохранено. После перезапуска файл ещё надо суметь прочитать.

До точного продолжения посреди эпохи тут далеко. Остаются порядок батчей, состояния генераторов случайных чисел, аугментации. Даже одинаковый seed не обещает одинаковый результат на другом железе или версии библиотеки.

Проверить на маленьком прогоне: обучение без остановки и обучение с восстановлением. Сначала на одном окружении, без обещания побитового совпадения где угодно. Такого прогона пока нет.

Отдельно: локальный checkpoint ничего не доказывает о внешнем платном запуске, если ответ на него пропал. Тут всё ещё нужно подтверждение от внешней системы.
