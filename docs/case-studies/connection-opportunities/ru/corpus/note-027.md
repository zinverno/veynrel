# «Временная ошибка» ещё не разрешение повторить запись

Запрос на чтение можно повторить после сетевого сбоя, если есть общий deadline. Ошибка авторизации или неверный вход обычно требуют изменения перед следующей попыткой. Ответ «слишком часто» должен влиять на паузу.

С записью сложнее. Транспортная ошибка может быть временной, а удалённая операция уже выполненной. Без контракта безопасного повтора одна классификация ошибок не поможет.

В логах хватит числа попыток и итогового статуса. Секреты и полные пользовательские данные туда не нужны. Лимит попыток должен оставаться конечным даже при долгой аварии; иначе одна задача займёт клиент навсегда.
