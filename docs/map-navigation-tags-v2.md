# Карта знаний: навигация и многотеговые зоны v2

Эта реализация продолжает PR #107 и его зависимую базу #106. Требование единственной основной зоны из ранней редакции **отменено**. Ни таксономия, ни раскладка не выбирают заметке исключительный главный тег.

## Причины и границы изменения

В v1 выбор менял множество точек (первые 80 либо соседи выбранной пары), после чего координаты нормализовались заново. «Вместить» сбрасывало камеру, но не выбор. Смысловые рёбра теряли score; ссылки и semantic edges имели одинаковую целевую длину. Вид постоянно резервировал три колонки, включая пустые сведения.

Теперь область данных, canonical selection, явное окружение, поиск/фильтр, видимые линии/зоны, камера, панели и expanded mode — отдельные состояния. Выбор и видимость слоёв не пересчитывают раскладку. PairReview остаётся прежним disposable owner: возврат восстанавливает визуальный контекст, но закрывает согласия и одноразовые tickets.

Writers, tickets, receipts, journal/recovery, providers, FSRS, embeddings, index format, cosine, eligibility, top-K и ranking не менялись. Stage 1.1 и старые команды сохранены. Повторные надписи Veynrel убраны из собственных breadcrumbs и главной; штатный title вкладки Obsidian сохранён.

## Визуальная грамматика

- Точка — один документ с точным canonical path. ◇ — существующий кандидат, не доказанная ошибка.
- Стрелка со сплошной линией — существующая направленная Markdown-ссылка. Пунктир — рассчитанное соседство.
- Мягкий контур с номером и названием — множество подтверждённых участников тега. Зоны имеют разные штрихи; цвет не является единственным кодом.
- Выбранный документ подсвечивает **все активные** зоны своего членства, соответствующие подписанные элементы и кольца вокруг точки. Скрытые членства и категории доступны в компактной панели.

Зоны состоят из ограниченных ячеек Вороного вокруг участников. Общие границы соседних ячеек одного тега удаляются. Это даёт пересечения и отдельные части, не заключая посторонний документ внутрь выпуклого hull. Ячейка не пересекает центр другой заметки; точное членство дополнительно видно при hover/focus зоны. Контур описывает членство, а не геометрическую семантическую классификацию.

Дополнительные visual instances не понадобились: один узел одновременно входит в несколько контуров. Инвентарь, кандидат, Compare, журнал и исполнение всегда считают уникальные файлы. Две проекции одного файла не могут образовать пару, поскольку в этой реализации их нет.

## Теги, фасеты и неизвестность

Host adapter использует `MetadataCache.getFileCache`, `getAllTags` и существующую `taxonomyToken`/taxonomy profile. Markdown не перечитывается. Frontmatter и inline tags объединяются без изменения написаний; множества избавляют только от точных повторов. Category multiplicity не отбрасывает реальные членства (включая theory + practice).

Иерархия использует `/`: `sql/cte` наследует `sql`, а `sql-old` — нет. Прямое и наследованное членство сохраняются отдельно, общий счётчик зоны уникален. Название настроенной категории берётся из profile; без него показывается буквальный `#prefix`, без выдуманной интерпретации.

Known empty отличается от unknown cache и stale metadata. Modify отмечает данные устаревшими до cache changed; rename/delete не переносят членство на другой путь. Временная неизвестность не стирает выбранную видимость слоёв. Explicit refresh обновляет только read-only cache projection.

Одновременно показано до 8 зон. Первоначальные 6 выбираются из разных доступных категорий с большим подтверждённым охватом; это только начальная видимость, не основной тег. Поиск/категория позволяют выбрать другие. Показаны числа скрытых зон; 100 строк в контроле тегов — ограничение детализации с поиском, не потеря членства.

Видимость зоны не меняет документы. Checkbox «Фильтр» включает настоящий фильтр; «Все выбранные (AND)» и «Любой выбранный (OR)» заданы явно. Фильтр показан отдельно и снимается одним действием. Счётчики зон пересекаются и не суммируются в размер vault. Зона не даёт write authority.

## Геометрия, камера и площадь

Raw semantic score, mutual и source revision проходят в read-only проекцию. Для доступного score используется ограниченное преобразование `(score + 1) / 2`; более высокий score уменьшает предпочтительную длину и усиливает притяжение. Исходный score не переписывается. Markdown-ссылки получают отдельную визуальную пружину, без semantic score. Отсутствующие рёбра не получают нулевых сходств.

Раскладка детерминирована: 32 конечных прохода для ≤500 документов, без таймерной симуляции. Это визуальное приближение с отталкиванием, не точная все-парная метрика. Теги не меняют геометрию. Кеш раскладки обновляется при изменении путей/рёбер/их provenance, а не при выборе, hover, слоях, wheel или resize.

До 500 документов показаны все. Для больших наборов список точных путей сохраняется, а обзор представляет все документы в ограниченных группах: лексикографические блоки по ≥100 путей, максимум 64 группы. Они подписаны диапазоном/общим префиксом и количеством, открывают детализацию, не Markdown/Compare. Это навигационная агрегация, не semantic cluster. Semantic cap остаётся 500 **eligible unique documents**; меньшее вычисление доступно через прежний выбор реальной папки.

Список и сведения — открываемые панели; без выбора нет пустой правой колонки. Pin явно выделяет место справа на широком pane. Expanded mode скрывает только собственную оболочку Veynrel в текущем ItemView; выход виден всегда. Узкий pane сохраняет переключатель списка и компактную панель выбора.

SVG viewBox подстраивается под пропорции pane с постоянным мировым центром. Wheel deltaMode нормализуется; anchor вычисляется через `getScreenCTM().inverse()`. Состояние камеры ограничено; DOM-transform объединяется максимум в один requestAnimationFrame. ResizeObserver и временные pointer listeners освобождаются при teardown. Capture начинается после 4 CSS px, drag не превращается в click; Enter после drag работает отдельно.

«Вместить», «Снять выделение», «Показать окружение», «К обзору» имеют разные действия. Возврат из окружения восстанавливает прежнюю камеру выбранной области. Escape принадлежит карте, уважает modal/menu и ввод текста; не отменяет исполнителя. Перенос существующего ItemView в popout сохраняет состояние.

## Проверки и воспроизведение

Скрипт `scripts/map-navigation-native.mjs` запускает настоящую установленную Obsidian/Electron в новом `/tmp/veynrel-workbench-*` profile. Источник — **существующий synthetic Lab**, который только читается и проверяется по SHA256. Новая самостоятельная генерация 1000 заметок не выполняется. Малые прогоны копируют нужный subset и две публичные synthetic executor fixtures; теговые overlays добавляются только в эти копии.

```
VEYNREL_LAB_ROOT=/absolute/path/to/synthetic-lab \
  node scripts/map-navigation-native.mjs /tmp/veynrel-workbench-new-run 154 /absolute/path/to/frozen-build
```

Размеры: `154`, `500`, `501`, `1000`. Векторы искусственные, deterministic; результат проверяет UI/navigation/provenance/cap, **не качество embedding-модели**. Для executor case только completion transport заменён локальным фиксированным JSON; реальные validator, planner, exact review, Apply, history и Undo проходят штатный маршрут. Нет платных API. Markdown после Undo сравнивается с исходным manifest, без копирования/восстановления в обход исполнителя.

## Установка

Доставка содержит frozen `main.js`, `manifest.json`, `styles.css`, `SHA256SUMS`, `SOURCE_COMMIT` и отдельный `install-to-test.sh` в постоянной папке вне `/tmp`. Локальная wrapper-команда фиксирует согласованный TEST vault; его личный путь не публикуется в Git. Generic installer проверяет хеши, отказывает оригинальному vault и symlink targets, сохраняет прежние три файла вне vault. Настройки, индекс, заметки и журналы не заменяет. Автоматическая установка в TEST не выполнялась.
