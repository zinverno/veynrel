# Veynrel 1.9.0

Draft release notes — release candidate only; not published.

Veynrel now brings vault health, semantic discovery, native recall, and its existing AI tools into one workspace: Health, Findings, Discover, Recall, Connect, Tools, and Settings.

## Veynrel Health

Review four dimensions: Structure, Connections, Recall, and Knowledge. Run local checks explicitly, inspect evidence in the Findings Inbox, and dismiss, snooze, or reopen findings. Scan receipts distinguish complete coverage from partial or outdated results. Opening the workspace does not scan or change notes.

An optional first-use profile helps describe how you use your vault. Existing users can skip it without running a scan. Recovery is scoped to the affected feature and preserves unrelated data.

## Discover

Search by meaning, find related notes, and review potential duplicates from one place. Semantic Intelligence setup reuses your existing embedding configuration and compatible local index. An explicit Semantic Health check can bring potential duplicates into Findings.

Semantic search, related-note comparison, duplicate discovery, and incremental indexing already existed in 1.8.0. This release integrates them into the workspace; it does not require rebuilding a compatible index.

## Native Recall

Veynrel now includes native spaced repetition with local FSRS-6 scheduling. No third-party review plugin is required. Find supported existing `Question::Answer` Markdown explicitly, reveal answers, and use Again, Hard, Good, or Easy. Discovery and review do not change notes.

Supported one-line cards belong under an ATX heading named `Flashcards`, such as `## Flashcards`. Bare pairs elsewhere and third-party review metadata are not imported. **Find flashcards** / **Refresh** is always explicit.

AI generation is a separate confirmed action on the selected note. It appends supported Markdown and ingests those cards into Recall while retaining existing schedules. A successful Markdown append followed by a failed Recall save is reported separately and can be recovered with Refresh.

## Knowledge Health

Deep Intelligence setup configures the existing language-model provider. Knowledge Health uses an explicit, confirmed LLM-assisted signal to identify notes that may be underdeveloped. It is not a fact checker, truth detector, or knowledge score. Old Deep Audit cache is not treated as proof of current Health coverage.

## Veynrel Connect

Connect gives the existing Companion bridge a dedicated setup and status surface. Test a connection, synchronize a disclosed mirror, and review proposed changes. External MCP clients can read and search the mirror and propose changes; they cannot directly write the Vault through this workflow. Applying a proposal requires explicit approval inside Obsidian.

Companion mirroring, MCP access, and proposals already shipped in 1.8.0. Protocol version 1 is unchanged; plugin 1.9.0 alone does not require a new server deployment.

## Tools and Settings

Tools keeps Ask your Vault, Deep Audit / Single Audit, batch processing, MOC generation, and legacy reports together. Existing editor actions, command IDs, and hotkeys remain available.

Settings summarizes each capability and its setup. Advanced controls remain available in Obsidian Settings, grouped by product area. Language-model, embedding, and Companion credentials stay independent. Failed settings saves restore the committed values without discarding newer edits.

## Upgrade and compatibility

- Same plugin ID: `ai-knowledge-hub`. Update normally; do not reinstall or create a new plugin folder.
- Existing settings, credentials, compatible semantic index, Companion vault identity, Deep Audit cache, notes, and user folders are retained.
- New Health and Recall stores are additive and may initially be missing. First opening Health offers the optional profile introduction; Skip performs no scan.
- Recall full-vault discovery remains explicit. Supported older native Recall schemas load in memory without migration writes; future schemas are blocked.
- Minimum declared Obsidian version remains 1.8.7; the manifest remains mobile-capable. Actual tested platforms and release coverage gaps are listed in the [release candidate report](../release-1.9.0.md), which is authoritative for platform claims.

## Privacy and data flow

Local Health checks and Recall scheduling stay local. Opening the workspace starts no expensive analysis or network work. Explicit Semantic indexing/search sends chunks or queries to the selected embedding provider; existing enabled synchronization can process subsequent Markdown changes. Deep/Knowledge analysis and AI authoring send the disclosed task input to the configured language model. Connect sends the disclosed mirror to its configured endpoint and requires Obsidian approval for proposals. Provider keys never go to Companion; its token never goes to AI providers; MCP credentials remain server-side.

Health findings/history, Recall persistence, Markdown-to-Recall authoring, and proposal write/acknowledgement are not one crash-atomic transaction. See [storage and recovery limits](../release-1.9.0.md) before managing these files manually.
