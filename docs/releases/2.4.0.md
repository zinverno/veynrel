# Veynrel 2.4.0 — release notes (pre-publication draft)

> **Release status:** Not published. This document is a candidate release description; it is not an installation receipt or a claim that all historical gates have passed.

## Highlights

- **Overview-first workspace:** a compact dashboard for findings, semantic search, tools, bulk auditing and Recall.
- **Local vault review:** visible source notes, evidence, filters and preparation for supported link/tag changes without writing from a passive view.
- **Semantic workflows:** separate results for the map, overlapping families, selected note pairs, neighborhoods, connection opportunities, global focus and similar notes. Semantic similarity does not establish duplication or justify an automatic edit.
- **Floating editor actions:** optional movable toolbar with source-bound selection; Style offers preview and a separate Apply with native Undo/Redo. Recall generation retains its existing confirmation, insertion and scheduling behavior.
- **Tools & Bulk Audit:** tool ring and explanations; Batch, Deep Audit, atomization and MOC presented clearly while keeping separate owners and recovery guarantees.
- **Safer streaming:** a streamed AI response is aborted on a change of destination note; late SSE chunks cannot be written into the newly opened note in the tested scenario.
- **Refined UI:** adaptive light/dark layout, keyboard routes, Obsidian theme variables and improved actions for findings.

## Retired or temporarily hidden

- Excalidraw diagram generation and its navigation are removed; existing user drawings are preserved.
- Studio UI and online Community catalog are temporarily hidden. Existing stored recipes and journals are retained; hidden code is not a promise of functional availability.

## Privacy and limitations

- Local checks and manual Recall do not require an AI key. Initial indexing requires an explicit action; depending on provider, note chunks or queries are sent to the configured embedding endpoint.
- Generative actions send the chosen source to the configured provider only after the relevant action/consent. Provider charges can still occur after cancellation.
- There is **no universal Undo** across Batch, Deep Audit, MOC and atomization; recovery is operation-specific.
- Global semantic focus has an existing documented eligibility cap (500), with explicit refusal when exceeded; no silent partial sampling.
- Semantic quality against real personal indexes has not been scientifically or comprehensively established. Synthetic native tests are not a real-provider benchmark.
- Mobile hardware, screen readers, physical GPU/compositor/IME and broad OS/theme compatibility remain unverified.

## Compatibility and upgrading

- Plugin ID remains `ai-knowledge-hub`; do not install into a second `veynrel` directory.
- The candidate requires Obsidian **1.13.7**. Linux desktop is the demonstrated host. The compatibility index keeps the 2.3.1 entry for 1.8.7 and the existing mobile eligibility. Physical mobile operation remains unverified. Settings use the host's declarative renderer and native refresh introduced in Obsidian 1.13.0. [Obsidian settings API](https://docs.obsidian.md/plugins/guides/migrate-declarative-settings).
- Before updating from 2.3.1: back up the vault, `.obsidian/plugins/ai-knowledge-hub/` (including `data.json`), indexes, Recall state, journal files and any user recipes.
- Install `main.js`, `manifest.json`, `styles.css` from **one identical 2.4.0 GitHub release**. Verify upgrade behavior and retention in a disposable copy first.
- Downgrade may require restoration of the matching backup if persisted formats have migrated; swapping only `main.js` is not a supported recovery guarantee.

A first substantive Recall mutation migrates v3 to v4 after saving the original bytes in `recall/cards.pre-v4-*.json`. To roll back, quit Obsidian, retain the entire post-upgrade vault separately, restore the complete matching pre-upgrade snapshot including the 2.3.1 runtime and reopen it. Check reviewed and retired cards and schedules before resuming. Reconcile intervening note edits separately.

## Scope and known limits

The owner moved 2.4.0 ahead of the planned R07 text portrait. A dedicated R07 PR is planned against 2.5.0. Resume Batch is deferred without an assigned version. Style refuses CRLF selections before requesting suggestions. Desktop host exceptions (`e.isShown`) and the cold 10,000-note readiness failure remain recorded. Focused checks give no broader host or performance guarantee.

Studio and Community are disabled before creating their runtime owners. Restoring an old Studio layout detaches its leaf. The historical Community confirmation/document-ownership defect remains a reactivation blocker. Explicit owner acceptance is required for the disabled-code risk and final candidate. [Release checklist](../../RELEASE_CHECKLIST.md).

The two fetch advisories are intentional. SSE needs incremental byte decoding, cancellation, timeout and HTTP errors. The dormant Community transport refuses redirects and enforces MIME and byte limits while reading. Obsidian's buffered request API cannot enforce both contracts. [Scanner review](../community-scanner-2026-11.md).

## Build identity

The reserved release tag is `2.4.0`. Run the following in two separate clean checkouts after tagging. The published provenance workflow independently rebuilds and compares all three bytestrings.

```sh
git checkout --detach 2.4.0
git rev-parse '2.4.0^{commit}'
npm ci
npm run build
sha256sum main.js manifest.json styles.css
```
