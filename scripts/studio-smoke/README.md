# Ручной smoke в отдельном синтетическом vault

Реальная модель — **NOT RE-EVALUATED**. Не используйте credentials, TEST-vault или рабочее хранилище. Комплект не содержит автоматической установки. Для полной автоматической native-проверки из checkout:

```sh
npm run build
node scripts/studio-source-preservation-native.mjs /tmp/veynrel-studio-native-YOUR-UNIQUE-ID
```

Скрипт требует Linux Obsidian/Electron 43 и создаёт отдельный профиль, synthetic vault, локальный HTTP responder. Его ответы заведомо синтетические, местами намеренно теряют фрагменты. Скрипт не подключает реальную модель. Старые native regression scripts также используют loopback; для Community не включайте `COMMUNITY_PUBLIC=1`.

Для ручного просмотра распакуйте новый review ZIP. Сверьте `sha256sum -c SHA256SUMS`. При необходимости **вручную**, после резервной копии, скопируйте только `build/main.js`, `build/styles.css`, `build/manifest.json` в `.obsidian/plugins/ai-knowledge-hub/` отдельного synthetic vault. Не переносите настройки из пользовательского vault. Галерея открывается через `python3 -m http.server 8765 --bind 127.0.0.1` из корня комплекта, затем `/gallery/`.

Для локального ручного запуска ответа: `python3 smoke-kit/loopback.py`; настройте в синтетическом vault Ollama-compatible URL `http://127.0.0.1:8766/v1`, модель `synthetic-source-preservation`, пустой ключ. Пустой ключ Ollama штатно передаётся как `Authorization: Bearer ollama`; responder разрешает только этот точный публичный маркер или отсутствие заголовка. Любой другой Authorization отклоняется без вывода значения. Responder принимает только bounded JSON на `/v1/chat/completions`; он не имеет удалённого backend и не ведёт лог тел запросов. Копируйте fixtures из `smoke-kit/vault` в одноразовый vault.

1. Выберите `Source.md` → встроенное форматирование → подготовка. Убедитесь, что политика YAML и точное исходящее тело видны до отдельного согласия отправки. Получите Review от loopback.
2. По умолчанию — отдельная заметка. Проверьте source → target, отсутствие id/aliases в финальном документе, строку источника и буквальный Markdown. Смените имя и назначение: генерации быть не должно. Разверните исходник, raw response, исключённый YAML, diff и конкретные замечания.
3. Создайте одну заметку. Сравните исходный SHA256 с `smoke-kit/SOURCE-SHA256SUMS`, созданный файл с точным preview. Результат не должен открыться сам. Через отдельную кнопку откройте source mode. После перезапуска проверьте историю.
4. Новый Review переключите на исходник. При замечаниях подтверждение требует отдельной неотмеченной галочки. Закройте редакторы исходника; примените и затем выполните защищённый Undo. Проверьте точный YAML и исходный хеш. Для BOM/CRLF fixture не открывайте исходник в редакторе: сам Obsidian может нормализовать его при сохранении; это отдельное от Studio действие.
5. Открытый сохранённый LF-исходник допускает create. Несохранённый буфер, включая popout, должен блокировать чтение/сохранение. Открытый редактор исходника блокирует inplace даже с совпадающим текстом. Закрытие редактора позволяет перепроверить тот же Review без генерации.
6. Выберите несколько источников, отметьте только часть результатов. Проверьте все пары до записи, исход каждого файла после. Занятый путь/каталог, target=source, другое расположение, case/Unicode collision или изменённый исходник должны отказать без overwrite/rename.
7. См. сохранённое fault-injection evidence: ошибка receipt после create даёт unconfirmed и останавливает batch. Перезапуск не повторяет запись; ручное подтверждение наблюдения записывает только квитанцию. Новым заметкам автоматический Undo/delete не предлагается.
8. RU/EN, светлая/тёмная тема, 390 px со свёрнутыми боковыми панелями, обычная ширина, split, Tab/Enter. Переключение назначения и status-события сохраняют выбранные строки и имена. Смысл автоматически не проверен при любом числе замечаний.

Физическое мобильное устройство, screen-reader speech, произвольные сторонние hooks, внешние межпроцессные гонки и ручная приёмка владельцем не входят в проведённую проверку.

Канонический responder хранится в `scripts/studio-smoke/loopback.py`; комплект собирается из этого файла без отдельной ручной правки. Проверка HTTP: `python3 scripts/studio-smoke/test_loopback.py`. Проверка production UI-маршрута: `node scripts/studio-source-preservation-native.mjs /tmp/veynrel-studio-native-UNIQUE /absolute/path/to/smoke-kit`. Наблюдатель теста записывает только status и категорию Authorization; он не изменяет входящие запросы или production transport.
